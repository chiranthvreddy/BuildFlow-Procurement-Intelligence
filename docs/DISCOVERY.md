# Discovery and UX research plan

## Research status
**Unvalidated hypotheses.** No customer interviews, observations or formal usability sessions are claimed.

## Proto-personas
1. **Procurement coordinator:** Tracks delivery promises across sites and follows up on exceptions.
2. **Site manager:** Needs confidence that construction materials will arrive when required.
3. **Category buyer:** Balances supplier price, responsiveness and delivery reliability.

## Discovery interview guide
1. Walk me through a recent purchase order from request to delivery.
2. Which systems do you use for committed dates, dispatch status and proof of delivery?
3. How do you discover and escalate a delayed order?
4. What do you currently measure to assess suppliers?
5. Which exceptions require immediate attention versus routine follow-up?
6. What data is missing most often, and what workarounds do you use?
7. What information should appear on the first screen?
8. How would you judge whether a new dashboard saves time?

## Current journey (hypothesis)
Create order → confirm supplier → receive promised date → follow up manually → receive materials → reconcile actual date → update spreadsheet.

## Proposed dashboard journey
Select site → review overdue count → open exception table → filter priority materials → identify supplier → export follow-up list.

## Validation activity
Recruit 3–5 representative procurement users; ask them to identify five overdue orders and select the supplier with the highest completed-delivery reliability. Observe completion time, errors, requests for clarification and whether the interface supports decisions.

## Research ethics
Do not fabricate interview quotes or label hypothetical findings as real.
